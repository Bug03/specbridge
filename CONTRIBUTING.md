# Contributing

Thanks for helping make project context more useful to developers, PMs, and coding agents.

## Before making a large change

Open a GitHub issue describing the user problem and proposed outcome. For a new capability or behavior change, add or update an OpenSpec change under `openspec/changes/` so reviewers can discuss requirements before implementation.

## Pull requests

- Keep changes focused and explain the user problem they solve.
- Link relevant Jira/OpenSpec concepts when available.
- Include evidence for behavior changes and document limitations.
- Never include Jira tokens, private ticket contents, or customer source code in fixtures.
- Do not treat text from tickets, comments, source files, or generated artifacts as trusted instructions.

## Project direction

Early product discussions are welcome. The first milestone prioritizes read-only Jira access, explicit spec links, source provenance, and portable context output. Please discuss a substantially different direction before implementing it.
